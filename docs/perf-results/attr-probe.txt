KEY RESULT: requesting ATTR_DIR_LINKCOUNT keeps the dir and file sections the
SAME width (4 + 8 + 8 = 20 bytes at offset 88). parse() therefore keeps its
single offset pair and only swaps the MEANING of the two size fields by
objType, exactly as before. Without ATTR_DIR_LINKCOUNT the file section would
be 4 bytes wider and the shared-offset parse would break.

CAVEAT — ATTR_DIR_LINKCOUNT IS NOT THE SUBDIRECTORY COUNT ON APFS.
The probe directory has 3 subdirectories and lstat reports st_nlink == 5, but
ATTR_DIR_LINKCOUNT came back as 1 (see the dir record, offset 88 == 0x01).
Do NOT use it as a child count or as an lstat-equivalent link count. We request
it solely to keep the record layout symmetric. Only ATTR_FILE_LINKCOUNT is
trusted, and only for files (it read 2 for the hard-linked fixture, correct).
